# Ambii mock server

The in-browser replacement for `ambii_business_server`, shared by the three Ambii demos (dashboard, web player, mobile app). It answers every request under `API_BASE` (`/projects/ambii-business/api`) inside the page, keeps the data in the visitor's browser, and sends nothing anywhere. The contract the apps rely on is in [`../README.md`](../README.md); this page is about the inside. What the demo holds and why (the music and its licences, the stations, the seed, how to add a track) is in [`docs/projects/ambii-business.md`](../../../docs/projects/ambii-business.md).

Plain ES modules with explicit `.js` specifiers, no syntax newer than ES2017 (no optional chaining, `??`, class fields or top-level `await`), no `class`, no dependencies. That way the same files run natively in a browser and bundle under the apps' webpack 4 (CRA 3 and 4, with their Babel) and webpack 5. The tools in `tools/` are Node scripts and may use anything.

## Using it

```js
import { installAmbiiDemo } from '<alias>/index.js'; // the apps alias it as "ambii-demo-mock"
installAmbiiDemo({ app: 'business' });               // before any other app code runs
```

`installAmbiiDemo(options)` is idempotent (a second call returns the first call's handle, also kept on `window.__ambiiDemo`). Options:

- `app`: `'business'`, `'player'` or `'music'`, informational.
- `badge`: `true` (default), `false`, or `{ position: 'bottom-right' | 'bottom-left' | 'top-right' | 'top-left', compact: true, style: '<extra css for the host>' }`.
- `latency`: `[min, max]` ms of simulated network delay (default `[100, 350]`).

Other exports: `API_BASE`, `resolveMediaUrl(url)`, `isTtsAnnouncement(ismOrUrl)`, `speakAnnouncement(ism, { volume })`, `cancelSpeech()`, `pauseSpeech()`, `resumeSpeech()`, `setSpeechBed(backgroundMusic)`, `notifyMediaPlaying()`, `resetDemo({ reload })`.

## How a request runs

1. `browser/transport.js` replaces `window.XMLHttpRequest` with a constructor that hands URLs under `API_BASE` (same origin) to the server and passes every other URL to the native XHR untouched, events and all (track audio, cover art, the apps' own files). It covers what axios 0.19 / 0.21 and antd's rc-upload use: `readyState` 1-2-3-4 with `onreadystatechange`, `onload`/`onloadend`/`onerror`/`ontimeout`/`onabort`, `upload.onprogress`, `responseType` `''`/`text`/`json`/`arraybuffer`/`blob`, response headers, `abort()`, `timeout`, and `send(FormData)`. `fetch` is wrapped the same way.
2. `core/server.js` `routeOf()` finds the `v3/(api|auth|public)/...` part of the path, so the mobile app's missing slash (`.../apiv3/api/...`) and trailing slashes still match. `API_BASE/media/<id>.mp3` serves uploaded audio from IndexedDB; `API_BASE/tts/<id>` serves a second of silence to anything that downloads a spoken announcement.
3. `matchRoute()` walks `ROUTES` in order, so specific templates come first (`announcement/upload/:id` before `announcement/:id`, `location/upload` before `location/:id`).
4. `transaction()` takes the cross-document lock (`navigator.locks`, name `ambii-demo-db`), waits for this document's localStorage to show the last commit (the fence: Chrome syncs localStorage between tabs asynchronously, IndexedDB is consistent), seeds when the stored `SEED_VERSION` differs, runs the handler, and commits the collections it changed. A handler that throws writes nothing and answers 500.
5. `identify()` picks the user and the business. The dashboard's sign-in stand-in sends a token as `Authorization: Bearer <token>`, and `account.userForToken()` maps it: `ambii-demo-newbiz` is the visitor's own business (user `61c0e0…01`, company `61c0c0…01`), created blank on first use like the server's `createUserIfNonExistent` at a first Auth0 sign-in (no company name, so the dashboard opens its sign-up modal; free plan; no locations; no `businessType`). Any other token (Sign In stores `ambii-demo-owner`), or none, is the seeded owner. On `/v3/auth/*` the token always decides, and the dashboard never gets a 401. On `/v3/api/*` an `ambii_player_jwt` header names a player, and its location's company is the business; an unknown or revoked one answers 401 `TOKEN_INVALID` (except on `connect`, where it is ignored). Without a player token the dashboard's token decides there too, which is what the dashboard's Assign (`POST /v3/api/station/:id`) needs.

## Where the mock departs from the server on purpose

Each is commented in the code.

- `GET /v3/api/station?page=n` returns items `(n-1)*15 .. n*15` (the server's `n*15` left the web player's side menu empty).
- `finishedTrack` answers a foreign device with the bare string `DEVICE_ALREADY_PAIRED` in `data`, which is what both players test for.
- A `finishedTrack` without a `scheduleId` key (the mobile app sends `trackScheduleId`) counts as "unknown schedule", not "new schedule", so its queue is not rebuilt at every track end.
- Ads follow `company.subscribed` for every queue (the server gave players ads whatever the plan). Each ad slot gets its own `_id` and `isrc` (`ADVERT_AMBII_<n>`), a `picture` and an `album.cover_large` (the Ambii logo). Subscribing or cancelling refreshes existing queues.
- `GET /v3/api/announcement` always returns the full list, with the hash under `announcementHash` and `messageHash`. `PATCH /v3/auth/announcement/:id` returns the updated announcement as `data` (the dashboard treats a missing `data` as failure).
- Zone `PATCH`/`DELETE` work (the server always answered 500). A second subscription cancel answers 400 "no subscription" instead of 500.
- `POST /v3/auth/card` is lenient and returns the whole card; only brand and the last four digits are ever stored.
- A refused subscription (no location, no card) changes nothing. The server switched every location, schedule and announcement on before those checks, so a free business that tried without a card was left with every store on. A subscription that goes through still switches them all on, as the server did, a store closed in the seed included.
- A player is shown online from `connect` (the server waited for its first `finishedTrack`), goes offline after 15 idle minutes (computed on read; longer for a track longer than that), and a device that connects elsewhere is unpaired from its previous location.
- Queues: the shuffle no longer drops a track, and downvotes apply to every queue built for that location and station.
- Schedule blocks: a block's tempo range is inclusive and its generated station is topped up to `MIN_DYNAMIC_TRACKS` (12) with the closest tempos (the server ignored tempo below 100 matching tracks, so with this catalogue tempo would never matter); a track whose first album genre is one of the block's ranks above one that only lists it second. Blocks may run past midnight and honour `days`. Time is the browser's local time. A schedule with no block covering "now" is still assigned (the location keeps its station until a block starts). `PATCH` may add blocks. Generated stations nothing points at are dropped.
- `company.businessType: 'cafe'` (not a server field) picks the dashboard's cafe rows for the seeded company. The visitor's own business has none, so it gets the restaurant rows, as every real customer did.
- `POST /v3/auth/location/upload`, the CSV location upload, existed only on the server's `develop` branch (`createMultipleLocationsAPI`, merged 2022-01-17, never deployed); `handlers/upload.js` follows it. Rows are checked like its Joi schema (400 with Joi's message for an empty upload, a wrong type, an unknown key or more than 1000 rows; 500 "State is invalid!" for a bad state), trimmed, states mapped to full names, and each created like `POST /v3/auth/location` (store code, zone, default station). The answer is `SUCCESSFUL_CREATE` with one `{ success, message, data: location }` per row; a row without a state fails on its own. On Premium every row is created active (the server's seat arithmetic made them all inactive once the company had an active location, against what the modal's billing note says); on the free plan the rows past the one free location are inactive, as on the server.
- Tracks carry a demo-only `credit` (guest tracks only): the licence and the artist's `label` from `guests.js`, or the host of their `site` when they have none (a library profile has a label, such as "Free Music Archive"), which all three players show under the artist.
- **Simulated in-store players** (demo only: `simulated: true` on a seeded player document). A store with one counts as playing whenever it is active (Online, `lastActive` now); a deactivated store goes Offline. Its Now Playing (`currentTrack`, `currentTrackNumber`, `lastTrack`) is worked out when a location is read: the time since its queue's `createdAt`, modulo the queue's length (ads included), walked through the durations (`simulatedPosition`). Nothing runs in the background and nothing is stored for it.
  - The dashboard's `GET /v3/auth/location` (and `/:id`) runs `followSchedule` first: a scheduled store moves to the block due now, with the new queue dated to the block's start (local time, so a daylight-saving day doesn't shift it), so it is mid-queue rather than on its first song. With no block due, a store already on one of its schedule's block stations moves to the block that began last, within the past week and honouring its days, as its player would have; a store on a station of its own keeps it (Weekend Brunch first seen on a weekday).
  - A real player connecting gets the usual take-over prompt. With override, `connect` first copies the simulated position into the location, so the real player starts on the song the store was playing, and the simulation stops for that store. Before that it catches the store up with its schedule, as the dashboard's next look would, so a block that began since anyone looked is joined partway through.
- **The Welcome announcement** (demo only: `demoAutoTime`). `connect` moves an announcement whose single "specific time" still equals its `demoAutoTime` to the next whole minute plus two, on that day, at each connect to one of its locations, so a short visit hears it once. Track ends and connects elsewhere leave it alone. Once the visitor edits its time, it no longer matches and stays where they put it.
- **Invoices** are shaped like Stripe's, with the customer's name, email and address copied on, the card's brand and last four, one line item with its quantity and unit price, and status times. `hosted_invoice_url` is `INVOICE_PAGE_URL?id=<id>` (`/projects/ambii-business/invoice.html`), which the dashboard opens. A new subscription's invoice bills the user who subscribed.
- **Spoken announcements:** an edit that changes a seeded recording's words, voice, language, speed or music bed switches it to browser speech (its recording has the old ones mixed in). Their stored `duration` includes the bed's lead and tail, as the server stored the mixed file's length.

## Storage

- localStorage, one key per collection: `ambii-demo:<collection>` (`{ id: doc }`), plus `ambii-demo:meta` (seed version, commit revision) and `ambii-demo:ui:badge` (the badge's size, kept across reseeds). The three demos run in separate documents of one origin, so every request reads the collections fresh.
- `ambii-demo:invoices` is also read by the hand-written `public/projects/ambii-business/invoice.html`, so its shape (invoice id → Stripe-shaped invoice) is a contract with that page.
- The visitor's own business (a second user and company, and whatever they make) lives in the same collections beside the seed; a reseed or `resetDemo()` removes it.
- IndexedDB database `ambii-demo`: store `media` (uploaded MP3s, keyed by announcement id) and store `meta` (the fence revision).
- `resetDemo()` clears every `ambii-demo:`, `ambii-business:`, `ambii-player:` and `ambii-music:` key in localStorage and sessionStorage, deletes the IndexedDB database and reloads.

## Media

Everything the catalogue and the announcements play is a file under `public/`; the catalogue names them through `core/media-data.js` and `core/bed-data.js`.

- **Jake's tracks:** `public/music/<slug>.mp3`, the 14 in `TRACKS` in `tools/build-media.mjs` (not copied; `super_bitch.wav` and tracks added since are left out), with titles and years from `musicList` in `src/common/constants.ts` (`TRACK_INFO` in `core/catalogue.js`). The seven over about 5 MB (`OWN_TRACKS_REENCODED` in `core/guests.js`) play from 128 kbps copies in `media/music/` (30 MB), because the players download each track whole.
- **Guest tracks:** `media/tracks/<slug>.mp3`, the 67 of `core/guests.js`, at 128 kbps (about 216 MB).
- **Art**, each at 640/320/120 px: `covers/` (Jake's tracks: the five with their own art use it, the rest have designs from `tools/covers.mjs`), `albums/` (one per guest album or single, drawn by `covers.mjs` `guestCover`: a style per main genre, and the covers in one style take the palettes in turn, so no two look alike), `artists/` (Jake's portrait and one drawn per guest artist) and `brand/` (the Ambii logo, from the dashboard's source).
- **Announcements:** `announcements/` (five) and `ads/` (the ad), spoken by Windows SAPI voices (Zira, David) and mixed over the Smooth bed where their `bed` is set, the way the server's sox pipeline did (3 s of bed on each side, fades); `beds/<n>.mp3`, the five synthesized music beds (2 Smooth, 3 Bright, 4 Light, 5 Distinct, 6 Mellow).
- `hub/` (the hub's screenshots) and `sample-locations.csv` (the CSV upload's sample) are made by hand.

The tools take their packages from a `node_modules` folder of their own, passed as `--deps` (or in `AMBII_MEDIA_DEPS`), never the site's. Run them from the repository root.

- **`tools/fetch-guest-tracks.mjs --deps <dir> [--cache <dir>] [--only a,b] [--force]`** (mpg123-decoder 1, @wasm-audio-decoders/ogg-vorbis 0.1, wasm-media-encoders 0.7). Downloads each guest track from its `file` into a cache outside the repository (default `<os tmpdir>/ambii-guest-cache`; each download notes its URL beside it, so a changed `file` is fetched again, and `--force` fetches everything again). It decodes it, brings it to -14 LUFS (about the median of Jake's tracks), encodes 128 kbps stereo with LAME compiled to WebAssembly, and writes `media/tracks/<slug>.mp3` with ID3 tags: title, artist, album, year, the licence and its URL, the source page, and a credit line. The encoded file must decode to a peak of at most 0.98; when it doesn't, it is encoded again quieter. It also makes the 128 kbps copies of Jake's larger tracks, at their own level, so a master that clips still clips a little in its copy (keeping "She wants my package" under 0.98 would leave it 2.6 dB quieter than the rest). `--only` limits it to those slugs (guest or Jake's), and a host that fails doesn't stop the others; they're listed at the end. `--measure <file> ...` prints the loudness, peak and an estimated tempo of local files and writes nothing. The output is committed, so this only runs to add or replace a track.
- **`tools/build-media.mjs --deps <dir> [mode]`** (sharp 0.33, lamejs 1.2.1, music-metadata 7). Draws the art, renders the clips and beds, measures the tracks, and writes `core/media-data.js`, `core/bed-data.js` and the hub's music credits (from `guests.js`, between the hub's `<!-- credits:start -->` and `<!-- credits:end -->` markers). It never touches the network, and never deletes anything in `media/`. With no mode it does everything, which needs Windows for the voices. The modes:
  - `--images-only`: the art only.
  - `--audio-only`: the beds, every clip, the measurements and the credits, but no art (Windows).
  - `--tracks-only`: re-measures Jake's tracks and the guests and rewrites the credits, keeping the clips already in `media-data.js`; runs anywhere.
  - `--beds-only`: the beds and `bed-data.js` only; runs anywhere.
  - `--clips-only [<id> ...]`: only the clips that are new or changed (no MP3 yet, not in `media-data.js`, or listed there with other words, folder or bed), or only the ones named. The other clips, the tracks and the credits stay as they are. A new voice alone isn't noticed, so name the clip to re-render it (Windows).
  - The logo is made from the dashboard's source, so where `demos/ambii/business-web/` isn't present (it isn't committed) the script keeps the logo already in `media/brand/`.
- **`tools/pick-stations.mjs [--write]`** (no packages). Picks each static station's tracks by genre and tempo, spreading them across stations (`SPECS`: genre wants, a preferred tempo range, a size and pinned tracks per station; a heavier penalty each time a track is reused; at most 7 stations per track beyond its pins; at most 4 tracks per artist), and prints each station's length, mean tempo and band, main genre, artists and worst overlap. `--write` rewrites `core/station-list.js` with explicit lists. It imports the catalogue, which refuses a station naming a track it no longer has, so after removing a track empty `STATION_INFO` (or take the track out of it) before running it.

Bump `SEED_VERSION` when durations, announcement texts, the catalogue or the stations change, and rebuild all three apps. Adding or removing a guest track, step by step, is in [`docs/projects/ambii-business.md`](../../../docs/projects/ambii-business.md#adding-or-removing-a-guest-track).

## Text-to-speech, sound and the badge

- Announcements created or previewed in the demo get `url: API_BASE/tts/<id>`. `speakAnnouncement()` speaks `message` with `speechSynthesis`, picking an on-device voice (never a network one, so the text stays in the browser) by the announcement's language and the gender of its Wavenet voice, at its `speed`. It always resolves: when the browser cannot speak (no voice, refused, never starts), it resolves after the time the words would take.
- It plays the announcement's music bed under the voice through Web Audio, on the server's sox timeline: `backgroundMusic` 2–6 picks a loop from `core/bed-data.js`; the bed fades in over 1.5 s, the voice starts 3 s in, the bed plays at 0.4 of the volume, holds 3 s after the voice and fades out over the last 1.5 s (`BED_TIMING`). There is no bed for 1 ("No Music") or a missing value, and a bed that can't load within 4 s, or an AudioContext the browser won't start, is left out, so the voice starts at once.
- The stored `duration` follows the same timeline: `spokenSeconds()` in `core/handlers/announcements.js` is the speech estimate (2.6 words a second at speed 1, at least 2 s) plus `BED_LEAD_SECONDS` and `BED_TAIL_SECONDS` (3 + 3) when there is a bed. `tts.js` takes its lead and tail from the same constants, so they can't drift apart. The web player's silent stand-in clip and progress bar follow `duration`.
- `cancelSpeech()` stops the voice and the bed at once. `pauseSpeech()` and `resumeSpeech()` pause and resume both with the timeline. `setSpeechBed(n)` crossfades to another bed while one is spoken (1 fades it out) and returns false when nothing is being spoken; the dashboard's preview uses it when Background Music changes. `speakAnnouncement` routes the page's own `speechSynthesis.cancel()`, `pause()` and `resume()` through these, so an app's existing calls stop or pause the bed too.
- The two players stop a spoken announcement with `cancelSpeech()` on Pause (and on skip, Disconnect and stop), and speak it again from the start on Play. They don't use `pauseSpeech()`: on Android `speechSynthesis.pause()` ends the utterance.
- `notifyMediaPlaying()` posts `{ type: 'jakemotta:media-playing' }` to `window.top` when framed. A capture-phase `play` listener covers `<audio>`/`<video>` in the document, and `HTMLMediaElement.prototype.play` is wrapped for detached `new Audio()` elements.
- The badge lives in a shadow root (the apps' CSS cannot reach it), starts compact below 560 px, and remembers its size. Twice a second it checks what is under it: if that is a fixed bar (a player bar, a toast) or, on a page that does not scroll or inside a modal, a control, it moves just past it, and back when it is gone.

## Adding a route

1. Write the handler in the matching `core/handlers/*.js`: `function (ctx) { ... return send('TYPE', data, 'Module'); }`. `ctx` has `tx` (`get`, `all`, `find`, `findOne`, `put`, `remove`), `now()`, `random()`, `params`, `query`, `headers`, `body`, `files`, `user`, `company`, `companyId` and `playerAuth` (`{ jwt }` for a player request). `user` and `company` are whichever business the request is for, the seeded one or the visitor's own, so use them rather than the seed's `IDS`. Return a promise when it needs one (uploads). Use the server's message type (`envelope.js`) and module name so the toast text matches the original.
2. Add `[method, 'v3/...', handler]` to `ROUTES` in `core/server.js`, above any more generic template it could be mistaken for.
3. Add a test in `test/` and run them. A dashboard route should be tried with both businesses' tokens (`test/dashboard.test.js` has the headers).

## Tests

- `node --test "test/*.test.js"` (from this folder, or `npm test`) runs the handlers against in-memory storage with a controllable clock (`test/helpers.js`):
  - `api.test.js`, `announcements.test.js`, `music.test.js`: the routes, the envelope and messages, queues, ads, schedules and announcements.
  - `seed.test.js`: the seven stores, the schedules on weekdays and weekends, the simulated players (Now Playing over time, following the schedule, a daylight-saving day, the take-over), the Welcome announcement, the invoices and the invoice page (hand-written, reads localStorage only, nothing from another host).
  - `dashboard.test.js`: the CSV location upload and the visitor's own business (sign-up, the free plan, Reset, a refused subscription).
  - `beds.test.js`: the bed files and `bed-data.js`, `speakAnnouncement()`'s timeline with fake Web Audio and `speechSynthesis`, the stored durations, and the seeded Welcome's clip.
  - `media.test.js` and `catalogue.test.js`: every media file the catalogue names exists (tracks, covers, portraits, clips, beds), the MP3 parser agrees with the stored durations and sizes, ids are unique and clear of the ads, and every track is on a station.
  - `syntax.test.js`: an ES2017 parse of every runtime file (uses `acorn` from the site's `node_modules`; skipped without it).
- Browser harness: `node test/browser/serve.mjs` (serves `public/` at `/` and `demos/` at `/demos/` on port 4111), then open `http://localhost:4111/demos/ambii/mock-server/test/browser/harness.html?run=1`. It runs real axios 0.19 and 0.21 builds (from the dashboard's and web player's `node_modules`, which exist only where the apps' source does, or `?axios=<url>,<url>`) through the XHR shim: envelope and errors, routing quirks, every `responseType`, `/music/*.mp3` downloaded as an `arraybuffer` through the native XHR, timeouts and cancels, an rc-upload multipart upload played back through `resolveMediaUrl`, `fetch`, speech and its silent stand-in, and the badge stepping above a fixed bar. Two tabs and an iframe (`child.html`) cover the shared data, the lock and the media-playing message when driven from a script.
