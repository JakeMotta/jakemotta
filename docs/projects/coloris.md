# Coloris

An unfinished top-down RPG Jake worked on in Greenfoot (Java) from October 2013 into 2014. Huey walks a scrolling map of forest, hills and stairs, and the number keys change his color. There are no enemies, goals or sounds yet; blood and injury effects are drawn but switched off in the code. The scrolling comes from danpost's `SWorld` class (v2.0, January 2013), shared on greenfoot.org. The folder is `public/projects/coloris/`; the card id is `coloris`.

## Preview

**Since 2026-10-27, `index.html` runs Coloris as JavaScript**, the first of the Greenfoot games to move off CheerpJ. `yarn projects:greenfoot coloris` takes the game's 28 classes out of `game-speed.jar` and `coloris.jar`, unchanged apart from renaming `java.awt.Color` and `Font`, and compiles them with TeaVM against our own Greenfoot runtime into `web/`: a 72 KB script and the 98 images it loads, about 2.4 MB in all. How that works, and how it compares with CheerpJ, is in [greenfoot-web.md](greenfoot-web.md). The page shows the 600×400 world at its own size (scaled down on a narrower screen), starts running on Play with no Run bar, and has Pause/Play and Start over under it. Coloris has no sound, so the site's music keeps playing.

**`cheerpj.html`** is the earlier page, kept for comparison until the other two games move: a copy of the isGuy page that runs the jar as an applet through CheerpJ, 616×469 (the world plus Greenfoot's border and control bar). See [isguy.md](isguy.md) for how that works and for CheerpJ's license. Nothing links to it.

Controls, from `Huey.java`: the arrow keys walk, and 1 to 6 set Huey's color (1 white, 2 black, 3 red, 4 green, 5 blue, 6 yellow).

**Which Coloris.** The archive has four copies:

| Folder | What it is |
| --- | --- |
| `Random/OldDropBox/Greenfoot/ColorisScroll/Coloris` | Source from October 2013 to March 2014, compiled on 2014-03-10 (Java 6). Three connected areas with hills, a cliff and stairs. **This one.** |
| `Coloris/Coloris2` | Source from June 2014, recompiled on 2017-05-10 (Java 8). One area; its stairs lead nowhere. |
| `Coloris/Coloris` | The June 2014 source with `gLevelOne` and `gLevelTwo`, but no compiled classes. Without a JDK it can't be built. |
| `Greenfoot/Coloris/Coloris` | A two-class prototype from late 2013. |

ColorisScroll has the most to walk around. Coloris2 also runs (it was built and tested the same way) and is the fallback if Jake prefers the later code.

**The jar is new.** Greenfoot never exported Coloris, so `coloris.jar` (5.7 MB, 491 entries) was assembled on 2026-10-26 from the ColorisScroll folder with a one-off Python script (`zipfile`; not kept). Nothing in it was changed or recompiled. In it:
- **The game:** ColorisScroll's 28 `.class` files and `project.greenfoot`, and its whole `images/` folder (29 files, including the 3.8 MB `RedMap.jpg`).
- **Its sprites:** the 85 files the source loads as `"../Sprites/…"` (Huey's walking frames in six colors, his brush, the blood and injury frames), from the `Sprites` folder beside the project. In the IDE, Greenfoot found them through the project's parent folder. In a jar each is stored twice:
  - `../Sprites/<path>` is the name Greenfoot's lookup, `getResource(name)`, finds;
  - `Sprites/<path>` is what Java then opens, because the `jar:` URL it gets back drops the `../`.

  The rest of the `Sprites` folder, including Pokémon Emerald sprite sheets, is unused and left out.
- **The Greenfoot 3.0.4 runtime:** `greenfoot/`, `bluej/`, `javazoom/` and the six control-bar icons (`greenfoot.png`, `noParking.png`, `pause.png`, `reset.png`, `run.png`, `step.png`), 260 entries copied byte for byte from `isGuyFinal.jar` ([isguy.md](isguy.md)). The classes were compiled against Greenfoot 2.x and run on it unchanged.
- **Settings:**
  - `standalone.properties` is `isGuyFinal.jar`'s, with `main.class=greenWorld` and `project.name=Coloris`;
  - `soundindex.list` is empty, since Coloris has no sounds;
  - the manifest names `greenfoot.export.GreenfootScenarioMain`, so `java -jar coloris.jar` runs it on the desktop too.

Two small jars sit in front of it in the applet's `archive`, both made on 2026-10-27:
- `game-speed.jar` (2 KB) holds `coloris.jar`'s `project.greenfoot` with one line changed, `simulation.speed=67` to `simulation.speed=50`. See Speed below. The JavaScript build reads it too.
- `browser-timer.jar` (2 KB) is isGuy's: Greenfoot's timer without its busy-wait, explained in [isguy.md](isguy.md#speed). Only `cheerpj.html` uses it.

`web/` is the JavaScript build's output, regenerated by `yarn projects:greenfoot coloris`; don't edit it by hand.

`poster.webp` is the starting view, 600×400, captured from the JavaScript build's canvas on 2026-10-27. It matches the earlier capture from CheerpJ, without Greenfoot's border and control bar.

**Speed.** ColorisScroll was saved at speed 67, where Greenfoot allows an act every 1.8 ms, so Coloris ran as fast as the browser could go: about 250 acts a second standalone (100 in the site's viewer), with the page's main thread always busy and only 20–50 frames a second drawn. Huey moves 2 pixels an act and changes walking frame every 10 acts, so at 250 he crossed the screen in about a second and his legs blurred. At Greenfoot's default speed 50 (an act every 16.2 ms) he walks about 120 pixels a second, with a step cycle of about two thirds of a second, the pace the code is written for and the speed isGuy and Pokémon run at. The 67 was most likely just where the IDE's speed slider was left. Measured standalone after the change, through CheerpJ: 53–57 acts a second, 55 frames drawn, main thread 70–78% busy; in the viewer about 46 acts and 38 frames, held back by the board ([isguy.md](isguy.md#speed)). As JavaScript: 59.3 acts and 58.6 frames a second in headless Chrome, main thread 27% busy, and 60.1 acts at 11% once the runtime looked collisions up by class (for Pokémon's town; [greenfoot-web.md](greenfoot-web.md#measured)). To get the old speed back, drop `game-speed.jar` from `jars` in the build's `GAMES` entry (and from `JARS` in `cheerpj.html`).

**The art.** The trees, grass and hills look like they come from a Pokémon tileset, and the `Sprites` folder holds Pokémon Emerald sheets. Where Huey's frames came from hasn't been checked.

**Verified:**
- with `java -jar` on the desktop: the jar opens with no errors (Coloris2 the same);
- in headless Chrome, served from `public/`: the map loads, Run starts it, walking scrolls the world, and the number keys change Huey's color;
- at 375 px wide, after scrolling the frame sideways to the Run button;
- inside a same-origin frame, Play leaves the parent page's music playing;
- with `game-speed.jar` and `browser-timer.jar`, on 2026-10-27: Run, walking and the scrolling, at the rates above;
- the JavaScript build, on 2026-10-27, served from `public/` by a static server: the starting view, walking and scrolling, the trees blocking Huey, the number keys, Pause and Start over, at 375 px wide (the world scales to fit), and in a same-origin frame with real key presses.

Also in the site's project viewer under `yarn dev`: Play, walking and the color keys, at 61 acts a second. Not verified for the JavaScript build: the blood and injury effects (switched off in the code).

**The world maps.** Since 2026-10-29, under the controls, the page shows Jake's pencil maps of Coloris's world, drawn screen by screen before the code: the town and the red, green, blue and yellow worlds. Jake approved them from the second sweep of his archive. They're scans from `Old Computer/Documents/Random/Stuff2/Old/Coloris/`, dated 2013-09-22, copied unchanged (2338×1700 JPEGs, about 0.5 MB each) into `maps/` under plain names: `town.jpg` (`TownMap.jpg`), `red-world.jpg`, `green-world.jpg`, `blue-world.jpg` (`<Color>World Map.jpg`) and `yellow-world.jpg` (`YellowWorld Map_002.jpg`, the later scan, with "Yellow" written in at the top; `_001` is the same page before that). Each is a link to its file and opens in a `<dialog>`, as in the Sketchbook. The `Human_*` PNGs beside them are character-generator exports, not Jake's drawings, and are left out.

## Download

`public/projects/coloris/download/coloris.zip` (5.6 MB), made on 2026-10-27, unzips to a `coloris/` folder:
- `coloris.jar`, unchanged;
- `play-coloris.jar` (2 KB), a launcher with no code: its manifest names `greenfoot.export.GreenfootScenarioMain` with `Class-Path: coloris.jar`, and it holds `game-speed.jar`'s `project.greenfoot`. Being first on the class path, that copy is the one Greenfoot reads, so the desktop game runs at speed 50 like the site's instead of the saved 67 (see Speed above). Its name can't be `Coloris.jar`: on Windows and macOS that's the same file as `coloris.jar`;
- `README.txt`: open `play-coloris.jar`, press Run, the controls.

A visitor needs Java 8 or newer and keeps the two jars together; it runs from any folder. `browser-timer.jar` is left out, since it only matters in CheerpJ. `coloris.jar` on its own still opens the game, at the old speed. Verified on 2026-10-27 with Java 25 on Windows 10: `java -jar play-coloris.jar` started from another folder opens the "Coloris" window with nothing on stderr. The speed itself wasn't measured on the desktop.

To rebuild: a short Python `zipfile` script writes the launcher (fixed entry dates, deflated) and zips the three files; it wasn't kept, and the steps above are all it does. The deploy compares files by size only (see CLAUDE.md), so a rebuilt zip of the same length wouldn't be uploaded: give it a new name.
