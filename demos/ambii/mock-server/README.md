# Ambii mock server

The in-browser replacement for `ambii_business_server`, shared by the three Ambii demos (dashboard, web player, mobile app). It answers every request under `API_BASE` (`/projects/ambii-business/api`) inside the page, keeps the data in the visitor's browser, and sends nothing anywhere. The contract the apps rely on is in [`../README.md`](../README.md); this page is about the inside.

Plain ES modules with explicit `.js` specifiers, no syntax newer than ES2017 (no optional chaining, `??`, class fields or top-level `await`), no `class`, no dependencies. That way the same files run natively in a browser and bundle under the apps' webpack 4 (CRA 3 and 4, with their Babel) and webpack 5.

## Using it

```js
import { installAmbiiDemo } from '<alias>/index.js'; // the apps alias it as "ambii-demo-mock"
installAmbiiDemo({ app: 'business' });               // before any other app code runs
```

`installAmbiiDemo(options)` is idempotent (a second call returns the first call's handle, also kept on `window.__ambiiDemo`). Options:

- `app`: `'business'`, `'player'` or `'music'`, informational.
- `badge`: `true` (default), `false`, or `{ position: 'bottom-right' | 'bottom-left' | 'top-right' | 'top-left', compact: true, style: '<extra css for the host>' }`.
- `latency`: `[min, max]` ms of simulated network delay (default `[100, 350]`).

Other exports: `API_BASE`, `resolveMediaUrl(url)`, `isTtsAnnouncement(ismOrUrl)`, `speakAnnouncement(ism, { volume })`, `cancelSpeech()`, `notifyMediaPlaying()`, `resetDemo({ reload })`.

## Layout

```
index.js            installAmbiiDemo, resetDemo, the cross-document lock; re-exports the browser helpers
config.js           constants: API_BASE, storage prefixes, SEED_VERSION, default station id, ad interval, latency
core/               environment-agnostic (no DOM); the node tests drive it directly
  server.js         routing table, request handling, transactions, identity (player tokens), seeding on demand
  store.js          localStorage collections, read fresh per request, written on commit
  envelope.js       the server's { success, message, type, data } envelope and message strings
  seed.js           the demo company
  catalogue.js      tracks, albums, the artist, the ad and the static stations (in code, not in storage)
  music.js          queues, ads, station assignment, schedule blocks and their generated stations, response shapes
  media-data.js     generated by tools/build-media.mjs: media URLs, measured durations, announcement texts
  mp3.js            MP3 duration from the bytes (uploads)
  voices.js         the Wavenet voice table of GET /v3/api/voices, voice gender and language helpers
  util.js           ids, codes, hashing, seeded PRNG, US states
  handlers/         one module per area: account, locations, stations, player, schedules, announcements, billing, misc
browser/
  transport.js      XMLHttpRequest and fetch replacements
  media.js          IndexedDB store for uploaded audio, resolveMediaUrl, the cross-tab fence
  tts.js            isTtsAnnouncement, speakAnnouncement, cancelSpeech
  notify.js         notifyMediaPlaying and the play listener
  badge.js          the demo badge
tools/              build-media.mjs and covers.mjs: regenerate public/projects/ambii-business/media/ and core/media-data.js
test/               node --test unit tests, and browser/ (the transport harness)
```

## How a request runs

1. `browser/transport.js` replaces `window.XMLHttpRequest` with a constructor that hands URLs under `API_BASE` (same origin) to the server and passes every other URL to the native XHR untouched, events and all (track audio, cover art, the apps' own files). It covers what axios 0.19 / 0.21 and antd's rc-upload use: `readyState` 1-2-3-4 with `onreadystatechange`, `onload`/`onloadend`/`onerror`/`ontimeout`/`onabort`, `upload.onprogress`, `responseType` `''`/`text`/`json`/`arraybuffer`/`blob`, response headers, `abort()`, `timeout`, and `send(FormData)`. `fetch` is wrapped the same way.
2. `core/server.js` `routeOf()` finds the `v3/(api|auth|public)/...` part of the path, so the mobile app's missing slash (`.../apiv3/api/...`) and trailing slashes still match. `API_BASE/media/<id>.mp3` serves uploaded audio from IndexedDB; `API_BASE/tts/<id>` serves a second of silence to anything that downloads a spoken announcement.
3. `matchRoute()` walks `ROUTES` in order, so specific templates come first (`announcement/upload/:id` before `announcement/:id`).
4. `transaction()` takes the cross-document lock (`navigator.locks`, name `ambii-demo-db`), waits for this document's localStorage to show the last commit (the fence: Chrome syncs localStorage between tabs asynchronously, IndexedDB is consistent), seeds when the stored `SEED_VERSION` differs, runs the handler, and commits the collections it changed. A handler that throws writes nothing and answers 500.
5. `identify()`: `/v3/auth/*` is always the seeded owner (the dashboard has no real sign-in, and never gets a 401). On `/v3/api/*` an `ambii_player_jwt` header names a player; an unknown or revoked one answers 401 `TOKEN_INVALID` (except on `connect`, where it is ignored). `Authorization` is ignored on `/v3/api/*`.

## Where the mock departs from the server on purpose

Each is commented in the code.

- `GET /v3/api/station?page=n` returns items `(n-1)*15 .. n*15` (the server's `n*15` left the web player's side menu empty).
- `finishedTrack` answers a foreign device with the bare string `DEVICE_ALREADY_PAIRED` in `data`, which is what both players test for.
- A `finishedTrack` without a `scheduleId` key (the mobile app sends `trackScheduleId`) counts as "unknown schedule", not "new schedule", so its queue is not rebuilt at every track end.
- Ads follow `company.subscribed` for every queue (the server gave players ads whatever the plan). Each ad slot gets its own `_id` and `isrc` (`ADVERT_AMBII_<n>`), a `picture` and an `album.cover_large` (the Ambii logo). Subscribing or cancelling refreshes existing queues.
- `GET /v3/api/announcement` always returns the full list, with the hash under `announcementHash` and `messageHash`. `PATCH /v3/auth/announcement/:id` returns the updated announcement as `data` (the dashboard treats a missing `data` as failure).
- Zone `PATCH`/`DELETE` work (the server always answered 500). A second subscription cancel answers 400 "no subscription" instead of 500.
- `POST /v3/auth/card` is lenient and returns the whole card; only brand and the last four digits are ever stored.
- A player is shown online from `connect` (the server waited for its first `finishedTrack`), goes offline after 15 idle minutes (computed on read; longer for a track longer than that), and a device that connects elsewhere is unpaired from its previous location.
- Queues: the shuffle no longer drops a track, and downvotes apply to every queue built for that location and station.
- Schedule blocks: a block's tempo range is inclusive and its generated station is topped up to `MIN_DYNAMIC_TRACKS` (8) with the closest tempos (the server ignored tempo below 100 matching tracks, so with 13 tracks tempo would never matter). Blocks may run past midnight and honour `days`. Time is the browser's local time. A schedule with no block covering "now" is still assigned (the location keeps its station until a block starts). `PATCH` may add blocks. Generated stations nothing points at are dropped.
- `company.businessType: 'cafe'` (not a server field) picks the dashboard's cafe rows.

## Storage

- localStorage, one key per collection: `ambii-demo:<collection>` (`{ id: doc }`), plus `ambii-demo:meta` (seed version, commit revision) and `ambii-demo:ui:badge` (the badge's size, kept across reseeds). The three demos run in separate documents of one origin, so every request reads the collections fresh.
- IndexedDB database `ambii-demo`: store `media` (uploaded MP3s, keyed by announcement id) and store `meta` (the fence revision).
- `resetDemo()` clears every `ambii-demo:`, `ambii-business:`, `ambii-player:` and `ambii-music:` key in localStorage and sessionStorage, deletes the IndexedDB database and reloads.

## Media

The catalogue is Jake's tracks in `public/music/*.mp3` (not copied; `super_bitch.wav` is left out), with titles and years from `musicList` in `src/common/constants.ts` and durations measured from the files. Everything else is in `public/projects/ambii-business/media/`: cover art per track at 640/320/120 px (`covers/`, the five tracks with their own art use it, the rest have generated designs), the artist portrait (`artists/`), the Ambii logo (`brand/`, from the upstream dashboard), the four announcements (`announcements/`) and the ad (`ads/`), spoken by Windows SAPI voices (Zira, David) and encoded with lamejs.

To regenerate (Windows only, no network): `node demos/ambii/mock-server/tools/build-media.mjs --deps <node_modules with sharp 0.33, lamejs 1.2.1 and music-metadata 7>` (`--images-only` / `--audio-only`). It rewrites `core/media-data.js`; bump `SEED_VERSION` if durations or announcement texts changed. The Ambii logo is made from the dashboard's source, so where `demos/ambii/business-web/` isn't present (it isn't committed) the script keeps the logo that's already in `media/brand/`.

## Text-to-speech, sound and the badge

- Announcements created or previewed in the demo get `url: API_BASE/tts/<id>`. `speakAnnouncement()` speaks `message` with `speechSynthesis`, picking an on-device voice (never a network one, so the text stays in the browser) by the announcement's language and the gender of its Wavenet voice, at its `speed`. It always resolves: when the browser cannot speak (no voice, refused, never starts), it resolves after the time the words would take, the same estimate as the announcement's `duration`.
- `notifyMediaPlaying()` posts `{ type: 'jakemotta:media-playing' }` to `window.top` when framed. A capture-phase `play` listener covers `<audio>`/`<video>` in the document, and `HTMLMediaElement.prototype.play` is wrapped for detached `new Audio()` elements.
- The badge lives in a shadow root (the apps' CSS cannot reach it), starts compact below 560 px, and remembers its size. Twice a second it checks what is under it: if that is a fixed bar (a player bar, a toast) or, on a page that does not scroll or inside a modal, a control, it moves just past it, and back when it is gone.

## Adding a route

1. Write the handler in the matching `core/handlers/*.js`: `function (ctx) { ... return send('TYPE', data, 'Module'); }`. `ctx` has `tx` (`get`, `all`, `find`, `findOne`, `put`, `remove`), `now()`, `random()`, `params`, `query`, `headers`, `body`, `files`, `user`, `company`, `companyId` and `playerAuth` (`{ jwt }` for a player request). Return a promise when it needs one (uploads). Use the server's message type (`envelope.js`) and module name so the toast text matches the original.
2. Add `[method, 'v3/...', handler]` to `ROUTES` in `core/server.js`, above any more generic template it could be mistaken for.
3. Add a test in `test/` and run them.

## Tests

- `node --test "test/*.test.js"` (from this folder, or `npm test`): handlers against in-memory storage with a controllable clock, the catalogue and media files, the music logic, and an ES2017 parse of every runtime file (uses `acorn` from the site's `node_modules`; skipped without it).
- Browser harness: `node test/browser/serve.mjs` (serves `public/` at `/` and `demos/` at `/demos/` on port 4111), then open `http://localhost:4111/demos/ambii/mock-server/test/browser/harness.html?run=1`. It runs real axios 0.19 and 0.21 builds (from the dashboard's and web player's `node_modules`, which exist only where the apps' source does, or `?axios=<url>,<url>`) through the XHR shim: envelope and errors, routing quirks, every `responseType`, `/music/*.mp3` downloaded as an `arraybuffer` through the native XHR, timeouts and cancels, an rc-upload multipart upload played back through `resolveMediaUrl`, `fetch`, speech and its silent stand-in, and the badge stepping above a fixed bar. Two tabs and an iframe (`child.html`) cover the shared data, the lock and the media-playing message when driven from a script.
